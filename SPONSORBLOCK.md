# Пропуск рекламных вставок в RussTube

Официальная база SponsorBlock перечисляет [YouTube как поддерживаемый сервис](https://wiki.sponsor.ajay.app/w/Types). Но существует отдельный проект [SponsorBlock for Rutube](https://greasyfork.org/en/scripts/562624-sponsorblock-for-rutube/code): пользовательский скрипт под лицензией MIT для браузера, использующий собственную базу RUTUBE. Лицензия скрипта сама по себе не определяет условия использования сервера и его данных. Это меняет план для RUTUBE; VK Видео, OK и Дзен пока требуют локальных отметок или других источников.

Скрипт извлекает ID из `/video/{id}`, читает `GET https://sponsorblock.futuba.ru/api/timestamps/{id}` и ожидает JSON `{"timestamps":[{"start":секунды,"end":секунды,"type":"skip"}]}`. Для отправки отметки он делает `POST` на тот же адрес с `start`, `end`, `type` и данными видео. Сам JavaScript в Android-плеер переносить не нужно: клиент может читать эти отметки и управлять Media3 напрямую. Однако 22 октября 2026 года домен `sponsorblock.futuba.ru` не разрешался в DNS при проверке из этой среды, поэтому работоспособность сервера и формат реального ответа не подтверждены. Не следует включать сетевой пропуск по умолчанию, пока сервер не станет доступен или не будет указан новый адрес.

Рабочая интеграция — реализовать общий механизм сегментов, а источник отметок выбирать по платформе: независимый API для RUTUBE, локальные отметки для остальных. Ключ записи: `платформа + канонический ID видео`, извлечённый из страницы видео, не из меняющегося адреса CDN. Отметки из API нужно проверять: `start >= 0`, `end > start`, конец не дальше длительности ролика, `type == "skip"`; переводить секунды в миллисекунды и ограничивать число сегментов. При недоступности API воспроизведение должно идти без задержки и без автоматических пропусков. Можно сохранить ручные отметки локально; общий сервер для остальных платформ и его модерация потребуют отдельного решения.

В `PlayerActivity` и `MobilePlayerActivity` можно подключить один общий `SegmentSkipController` к Media3 `Player.Listener` и существующему секундному таймеру. Контроллер получает сегменты для текущего `VideoItem`, показывает цветные участки на шкале и при входе в сегмент выполняет `seekTo(endMs)` только один раз. При ручной перемотке состояние сбрасывается; рядом с сообщением о пропуске нужна кнопка «Вернуть» для возврата к началу. Автопропуск следует разрешить по категориям (`sponsor`, `intro`, `outro`, `selfpromo`), а для агрессивной категории `filler` оставить ручной режим — это соответствует [предупреждению проекта](https://wiki.sponsor.ajay.app/w/Types). Для прямых эфиров, роликов без определённой длительности и сегментов за пределами длительности пропуск отключается.

В настройках плеера нужны переключатель функции, режим «спросить/пропустить», выбор категорий и опция использования общей базы. По умолчанию сетевые запросы к такой базе стоит выключить: они раскрывают, какое видео открыто. Если RussTube когда-либо будет открывать достоверно сопоставленный оригинал YouTube, для него можно отдельно использовать официальный API, включая [запрос по префиксу SHA-256 ID](https://wiki.sponsor.ajay.app/w/API_Docs) для большей приватности. Перед использованием данных или кода SponsorBlock нужно проверить условия [лицензии, на которую ссылается документация API](https://wiki.sponsor.ajay.app/w/API_Docs), и указать атрибуцию.

Предлагаемая последовательность: (1) общий контроллер пропуска и локальные сегменты в обоих плеерах; (2) опциональный клиент независимого RUTUBE API после проверки рабочего адреса и ответа; (3) разметка начала/конца с пульта и телефона; (4) общая база для остальных платформ, только если появится потребность в синхронизации. Название общей настройки лучше «Пропуск вставок», а источник RUTUBE указать отдельно, чтобы не обещать покрытие всех четырёх платформ.
