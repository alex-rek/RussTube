# Вход в аккаунт RUTUBE

В обеих версиях RussTube вход необязателен. Настройки открывают страницу `https://rutube.ru/my/` внутри Android WebView. Пользователь вводит телефон, почту и пароль только на странице RUTUBE; RussTube не получает эти значения и не сохраняет их. После входа кнопка «Проверить вход» запрашивает `https://rutube.ru/api/profile/user?picture_type=ios` с cookie WebView. Только подтверждённый профиль активирует сеанс в приложении.

Cookie остаются в приватном хранилище WebView. В обычных настройках RussTube хранится только отображаемое имя профиля. При выходе локальный сеанс и cookie WebView удаляются. Резервное копирование данных приложения отключено. Авторизованные cookie добавляются лишь к HTTPS-запросам `rutube.ru/api/`, без автоматического следования перенаправлениям; запросы к CDN и другим площадкам их не получают.

Локальные подписки и избранное RussTube не меняются и не передаются в аккаунт RUTUBE. Вход не включает автоматическую синхронизацию истории, подписок или оценок. Если на устройстве нет Android WebView, экран входа показывает сообщение об этом.

При включённом прокси для площадки RUTUBE страница входа WebView получает тот же HTTP- или SOCKS5-прокси до загрузки страницы; после закрытия экрана настройка WebView снимается. Проверка профиля уже использует `NetworkProxy.openConnection("RUTUBE", ...)`, включая логин и пароль HTTP-прокси. Если WebView устройства не поддерживает настройку прокси, страница входа не открывается напрямую: пользователь видит ошибку. Chromium WebView не поддерживает SOCKS5-аутентификацию логином и паролем, поэтому для страницы входа в таком случае нужен HTTP-прокси или системный прокси. Для QR-входа по коду устройства необходим собственный `client_id` RussTube, выданный RUTUBE; идентификатор из другого приложения не используется.

Проверено на эмуляторе: страница RUTUBE и форма входа открываются в Mobile, проверка анонимного сеанса возвращает сообщение о незавершённом входе; страница также открывается из настроек TV, а фокус возвращается на пункт входа. В TV стрелки пульта перемещают фокус по элементам веб-страницы, OK подтверждает выбор; так удалось открыть форму входа. Сборка, модульные тесты и lint проходят для обоих вариантов. Успешный вход, обновление cookie и воспроизведение в авторизованном сеансе требуют проверки с тестовым аккаунтом RUTUBE.

Проверка прокси на мобильном эмуляторе: без прокси страница входа открылась; с недоступным HTTP-прокси WebView показал `ERR_PROXY_CONNECTION_FAILED`, а проверка аккаунта сообщила об ошибке соединения с тем же прокси. С локальным тестовым HTTP-прокси, требующим Basic-аутентификации, страница входа отправила повторный `CONNECT` с учётными данными; проверка профиля также отправила авторизованный `CONNECT`. Тестовый прокси намеренно не передавал трафик дальше, поэтому успешный вход через реальный прокси этим тестом не подтверждён. Настройки эмулятора после проверки возвращены к состоянию «Без прокси».
