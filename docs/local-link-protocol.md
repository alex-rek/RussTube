# Локальная связь RussTube Mobile ↔ TV

Реализация следует [аудиту](local-sync-audit.md) и уточнению пользователя: структура подписок и избранного не меняется, по сети выполняется только их аддитивное объединение. История, позиции, плейлисты, настройки и каталог телеканалов не передаются. Управление TV работает отдельно от синхронизации библиотеки.

## Подключение

- Оба приложения должны быть открыты и иметь доступ к одной домашней сети. В настройках включить локальное соединение.
- TV: **Настройки → Синхронизация → Подключить устройство**. QR-код и восьмизначный ручной код действуют две минуты.
- Mobile: **Вы → Настройки → Устройства**. Отсканировать QR-код либо ввести локальный IP TV, порт и код. При ручном вводе сравнить показанный короткий отпечаток сертификата с экраном TV.
- Подтвердить запрос на TV. После сопряжения устройства сохраняют идентификаторы и отпечатки сертификатов. Пользователь может отключить управление/запуск с конкретного телефона либо удалить сопряжение.
- Если mDNS недоступен, ручной ввод адреса остаётся резервным способом. При смене адреса обнаружение может найти TV снова; при недоступном multicast может потребоваться повторное ручное подключение.

## Транспорт и безопасность

Android NSD объявляет `_russtube._tcp.` с UUID, типом устройства, именем и версией. Объявление не содержит пользовательских данных, токенов и ключей. Соединение использует платформенный TLS с взаимными сертификатами EC из Android Keystore. После TLS проверяется сохранённый SHA-256 отпечаток сертификата. Несопряжённый клиент допускается только к ограниченной одноразовой процедуре сопряжения, требующей подтверждения на TV. Для остальных сообщений проверяются идентификатор устройства, версия протокола и монотонный номер сообщения. Транспорт не использует прокси видеоплощадок и не содержит внешнего relay.

Протокол версии 1: `uint32` длина и UTF-8 JSON, максимум 4 МиБ. Поля: `protocolVersion`, `messageId` (UUID), `deviceId` (UUID), `type`, `sequence` (положительное целое), `payload` (объект). Типы: `HELLO`, `PAIR_REQUEST`, `PAIR_RESULT`, `SYNC_REQUEST`, `SYNC_CHANGES`, `SYNC_ACK`, `PLAYBACK_COMMAND`, `PLAYBACK_STATE`, `CAPABILITIES`, `ERROR`, `PING`, `PONG`. Сообщения после сопряжения принимаются только с закреплённого сертификата. В одной сессии допускается не более 30 входящих сообщений в секунду. Heartbeat отправляется каждые 10 секунд.

`SYNC_CHANGES` использует существующий формат `russtube-library` v1, но перед отправкой удаляются адреса миниатюр, query-параметры и временные URL потоков. Данные ограничены 100 подписками и 1000 избранными видео. Импорт выполняет объединение без дубликатов, сохраняет локальный порядок и добавляет новые записи. Удаления между устройствами не передаются: удалённая запись может вернуться после следующего объединения. Две записи SharedPreferences не образуют аппаратную транзакцию; при ошибке второго сохранения выполняется попытка восстановления первого.

`PLAYBACK_COMMAND` допускает `PLAY`, `PAUSE`, `TOGGLE_PLAY_PAUSE`, `STOP`, `SEEK_TO`, `SEEK_FORWARD`, `SEEK_BACKWARD`, `SET_PLAYBACK_SPEED`, `OPEN_VIDEO`, `GET_PLAYBACK_STATE`, `GET_CAPABILITIES`, а также `DPAD_UP/DOWN/LEFT/RIGHT`, `OK`, `BACK` внутри приложения. Команды, которым требуется открытый плеер, возвращают ошибку, когда он закрыт. `OPEN_VIDEO` передаёт платформу, тип, постоянный ID и безопасные метаданные; TV самостоятельно запрашивает поток через существующий резолвер. Временный адрес видео с телефона не передаётся. Пульт не управляет системой Android TV.

## Диагностика и ограничения

При ошибке экран устройств показывает краткое сообщение. `adb logcat -s RussTubeLocalLink` показывает тип ошибки без кодов сопряжения и ключей. В настройках отображается время последнего обмена. Постоянная фоновая служба не запускается: соединение доступно, пока приложение открыто. Проверка на реальных Wi-Fi/Ethernet устройствах, при смене сети и на Android 17 остаётся отдельным приёмочным шагом.
