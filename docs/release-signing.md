# Подпись выпусков RussTube

Выпуски Mobile и TV 0.6.15–0.6.21 были опубликованы как debug APK. Все локально сохранённые APK этих выпусков имеют SHA-256 отпечаток сертификата:

`195c199e4efd02951a001e28a09c77c664f32b28d3c707143ee0aaa3a6e6e1a7`

Проверка выполнена `apksigner verify --print-certs`. Это отпечаток открытого сертификата, не секретный ключ. Для установки новой версии поверх существующей Android требует совместимую подпись. Поэтому автоматическая публикация в `release.yml` прекращается, если отпечаток подготовленного APK отличается. Это ограничение действует и для Mobile, и для TV.

## Настройка автоматического выпуска

Workflow запускается при отправке тега `v<versionName>`. До публикации он проверяет совпадение тега с `app/build.gradle`, запускает тесты и lint, собирает оба варианта с R8, проверяет выравнивание и подпись, затем прикрепляет APK и SHA-256 к GitHub Release. Карты R8 сохраняются как отдельный артефакт Actions.

В GitHub Actions должны быть созданы секреты:

- `RELEASE_KEYSTORE_BASE64` — содержимое **существующего** файла ключа в Base64;
- `RELEASE_STORE_PASSWORD`;
- `RELEASE_KEY_ALIAS`;
- `RELEASE_KEY_PASSWORD`.

После настройки секретов установите переменную Actions `SIGNED_RELEASE_ENABLED=true`. До этого job публикации пропускается; локальная сборка и ручная загрузка релиза не используют секреты GitHub.

Ключ, которым будут подписаны APK, должен иметь указанный выше отпечаток. Не помещайте файл ключа, пароли или Base64 в репозиторий, логи и артефакты сборки. Сохраните резервную копию файла ключа вне GitHub и проверьте установку обновления поверх опубликованного APK на Mobile и TV до первого автоматического выпуска.

Текущая локальная конфигурация не содержит этих секретов. Наличие самого debug-ключа на компьютере сборки не означает, что его безопасно использовать для долгосрочного распространения. Если будет выбран новый ключ, сначала нужен отдельный план переноса данных пользователей; простая замена ключа не обновит установленные приложения.

`UpdateManager` теперь предлагает только APK без суффикса `-debug`. Уже опубликованные debug APK остаются на странице предыдущих выпусков, но новый автоматический выпуск невозможен до настройки совместимого ключа. Ссылка README ведёт на страницу последнего выпуска и не содержит устаревающее имя APK.
